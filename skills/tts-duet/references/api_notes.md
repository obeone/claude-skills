# Gemini TTS — API Notes

Operational quirks of the Gemini TTS preview models that matter when
wiring them into the skill. Update carefully — the pricing block is
auto-generated.

## Models

The skill targets **preview** models:

- `gemini-2.5-pro-preview-tts` — higher fidelity, default for
  production runs.
- `gemini-2.5-flash-preview-tts` — cheaper, default for auditions and
  CI smoke tests.

The SDK also accepts future model IDs verbatim; see the `--model` flag
on `generate_tts.py` and `estimate_cost.py`.

## PCM-not-WAV response shape

`generate_content` with `response_modalities=["AUDIO"]` returns **raw
PCM** (little-endian signed 16-bit, 24 kHz, mono) in
`response.candidates[*].content.parts[*].inline_data.data`. There is no
WAV header on the wire; the skill wraps the payload in a WAV container
via `lib.audio_io.pcm_to_wav`.

```python
pcm = b""
for candidate in response.candidates or []:
    for part in (candidate.content.parts or []):
        if part.inline_data and part.inline_data.data:
            pcm += part.inline_data.data
# 24 kHz, 16-bit, mono:
audio_io.pcm_to_wav(pcm, Path("out.wav"))
```

## Multi-speaker config requirements

For dual-voice generation the content **must** use the exact labels
`Speaker1:` and `Speaker2:`. The parser normalizes `Speaker A` /
`Speaker B` inputs to these. Mismatched labels silently fall back to
the first voice for the entire clip.

```python
types.MultiSpeakerVoiceConfig(speaker_voice_configs=[
    types.SpeakerVoiceConfig(speaker="Speaker1", voice_config=...),
    types.SpeakerVoiceConfig(speaker="Speaker2", voice_config=...),
])
```

Only **two** speakers are supported. Scripts with three or more voices
must be split upstream.

## System-instruction compatibility

Spike `_spike_system_instruction.py` determines the flag value in
`lib/_config.py`. On pass → notes go via `system_instruction`; on fail
→ inline sentinel `[director-notes-do-not-speak]` with per-chunk
duplication.

**Current status**: spike **FAILED** against `gemini-2.5-flash-preview-tts`
(SDK `google-genai>=1.0`). Baseline TTS calls (no
`system_instruction`) return audio normally; adding `system_instruction`
alongside `response_modalities=["AUDIO"]` causes consistent
`ServerError: 500 INTERNAL` across retries. The flag
`USE_SYSTEM_INSTRUCTION_FOR_NOTES` is therefore shipped as `False` and
the inline-sentinel fallback is in use. Re-run the spike after an SDK
bump and flip the flag if the server accepts the combination.

## Heuristic calibration

`OUTPUT_TOKENS_PER_SECOND` in `scripts/lib/pricing.py` is a rough
constant (1000 tokens ≈ 1 second of audio). Recalibrate after the first
ten real generations if the observed mean deviates by more than ±10 %
from the embedded value; the ±30 % estimate band published by
`estimate_cost.py --json` can be narrowed in the same change (ADR
follow-up (e)).

## Rate limits / context window

- **Input context**: 32 000 tokens per call. The skill's default
  `--max-input-tokens 30000` leaves a small safety margin.
- **Voices per call**: two (one in mono mode).
- **Language support**: 100+ languages auto-detected; the `--lang`
  flag is advisory only (it biases pronunciation via
  `system_instruction` but does not force the output language).
- **Audio parameters**: 24 kHz, 16-bit, mono — same across pro/flash.
