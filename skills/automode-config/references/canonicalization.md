# Canonicalization

The byte-level contract for serialized `autoMode` proposals. Every
write path goes through `_canonical.canonical(obj) -> bytes`. The
hash gate operates on the result of this function.

## Byte contract

- `json.dumps(obj, sort_keys=True, indent=2, ensure_ascii=False)`.
- LF line endings (no CRLF, ever).
- Trailing newline (one `\n` after the closing `}`).
- UTF-8, no BOM.
- The output is bytes, not str: `canonical(obj) -> bytes`.

The contract is intentionally narrow. Two proposals that round-trip
to the same canonical bytes are byte-equal; the hash gate uses
`sha256(canonical(proposal))`.

## Round-trip property

For any proposal `p`:

```
load_json(canonical(p)) == p
canonical(load_json(canonical(p))) == canonical(p)
```

Idempotency holds across re-canonicalization: feeding canonical bytes
back through `load_json -> canonical` yields identical bytes.

## Fixture format

`tests/fixtures/canonical/` holds 50 paired files:

- `in_NN.json` — input (any valid JSON, any whitespace, any key
  order).
- `out_NN.json` — expected canonical bytes for `in_NN`.

Numbering: `00..49`, zero-padded to two digits. The first ten are
hand-curated edge cases (Unicode escapes, deep nesting, mixed types,
the `__example_only` structural wrapper, the `$defaults` sentinel).
The remaining forty are generated by `_generate.py` with seed
`20260508`.

## Edge cases the fixtures must cover

- Unicode strings (BMP and astral plane). `ensure_ascii=False`
  preserves the original UTF-8.
- Numbers at the JSON edge (negative zero serializes as `0`; floats
  round-trip; integers preserve their type).
- Empty arrays and empty objects.
- Deeply nested objects (at least one fixture with depth >= 6).
- Objects with keys that sort non-alphabetically without `sort_keys`
  (insertion-order test).
- The `__example_only` structural wrapper:
  `{"__example_only": true, "value": <any>}` — canonical form keeps
  both keys; the loader strips the wrapper at runtime, but
  canonicalization itself does not interpret the marker.
- The `__example_only` substring inside a string value: preserved
  verbatim.
- The `$defaults` sentinel inside `autoMode.environment`: preserved
  verbatim, position retained (the array is not sorted).

## `parse_flat_yaml` semantics

`assets/heuristics.yaml` is written in a hand-rolled flat-YAML format
and is read through `parse_flat_yaml` to keep the foundations
stdlib-only. `assets/dropped_rules.yaml` is written in the same format
but that is where the similarity ends: nothing calls `parse_flat_yaml`
on it, or reads it at all (see `references/migration.md`, "What
`[e]dit` accepts"). The rules below describe the format both files
happen to use, not what happens to either file at runtime.

- Lines starting with `#` are comments and skipped.
- Blank lines are skipped.
- Every other line must match `^([A-Za-z_][A-Za-z0-9_]*): (.+)$`.
  - The key is up to the first `: ` (colon + single space).
  - The value is the remainder of the line, no escape processing.
- No nesting, no lists, no anchors, no flow style, no empty values.
  A line `key: ` (trailing space, empty value) is a parse error.
- Duplicate keys are a parse error.
- Output: `dict[str, str]` preserving insertion order.

The parser is intentionally rigid. Anything richer than `key: value`
must be expressed as multiple top-level keys.
